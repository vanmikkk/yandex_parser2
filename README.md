# Yandex Reviews Parser

SPA-приложение для авторизации пользователя, сохранения ссылки на организацию в Яндекс Картах и фонового сбора отзывов с отображением результатов с пагинацией.

## Стек

### Backend

- PHP 8.5
- Laravel 12
- Laravel Sanctum
- MySQL
- Laravel Queue
- Puppeteer / Node.js

### Frontend

- Vue 3
- Composition API
- Vite

## Возможности

- авторизация по логину и паролю;
- один тестовый пользователь, регистрация отсутствует;
- сохранение ссылки на организацию в Яндекс Картах;
- валидация URL;
- получение информации об организации:
  - название;
  - рейтинг;
  - количество оценок;
  - количество отзывов;
- получение доступных отзывов;
- сбор до 600 последних опубликованных отзывов;
- пагинация отзывов по 50 элементов;
- отображение:
  - автора;
  - даты;
  - текста;
  - оценки;
- запуск парсинга в фоне через Laravel Queue;
- отображение прогресса парсинга;
- повторный запуск парсинга;
- обработка ошибок парсинга.

Яндекс официально указывает, что в Картах и Яндекс Бизнесе доступны последние 600 опубликованных отзывов. Поэтому приложение ограничивает количество сохраняемых отзывов 600 элементами. 

# API

Все API-методы приложения находятся под `/api`.

Защищённые endpoints требуют аутентификации через Laravel Sanctum. Для first-party SPA Sanctum использует cookie-based session authentication и CSRF-защиту. citeturn0search0

## Authentication

### `POST /login`

Авторизация пользователя.

**Request:**

```json
{
    "email": "test@example.com",
    "password": "password"
}
```

**Success: `204 No Content`**

После успешной авторизации Laravel создаёт сессию, которая используется последующими запросами SPA.

### `POST /logout`

Завершает текущую пользовательскую сессию.

**Response: `204 No Content`**

### `GET /api/me`

Возвращает текущего авторизованного пользователя.

**Response:**

```json
{
    "user": {
        "id": 1,
        "name": "Test User",
        "email": "test@example.com"
    }
}
```

Если пользователь не авторизован:

```text
401 Unauthorized
```

# Organization API

## `GET /api/organization`

Возвращает сохранённую организацию и текущее состояние парсинга.

**Response:**

```json
{
    "organization": {
        "id": 1,
        "yandex_url": "https://yandex.ru/maps/...",
        "yandex_id": null,
        "name": "Название организации",
        "rating": "4.80",
        "ratings_count": 1250,
        "reviews_count": 473,
        "last_parsed_at": "2026-09-16T10:30:00.000000Z",
        "parse_status": "completed",
        "parse_progress": 100,
        "parse_error": null
    }
}
```

Возможные значения `parse_status`:

```text
idle
running
completed
failed
```

Frontend использует этот endpoint для отображения текущего состояния фонового парсинга.

## `POST /api/organization`

Сохраняет URL организации и запускает парсинг.

**Request:**

```json
{
    "yandex_url": "https://yandex.ru/maps/..."
}
```

Перед сохранением выполняется серверная валидация URL.

Проверяются:

- корректность URL;
- домен Яндекс;
- путь `/maps`;
- наличие раздела отзывов.

**Success: `202 Accepted`**

```json
{
    "message": "Organization saved. Parsing started.",
    "organization": {
        "id": 1,
        "yandex_url": "https://yandex.ru/maps/...",
        "parse_status": "running",
        "parse_progress": 0,
        "parse_error": null
    }
}
```

Сам парсинг внутри HTTP-запроса не выполняется. Endpoint только сохраняет настройки и ставит `ParseOrganizationReviewsJob` в очередь.

Если парсинг уже выполняется:

```text
409 Conflict
```

## `POST /api/organization/refresh`

Повторно запускает парсинг сохранённой организации.

**Request body:** отсутствует.

**Success: `202 Accepted`**

```json
{
    "message": "Parsing started.",
    "organization": {
        "id": 1,
        "parse_status": "running",
        "parse_progress": 0,
        "parse_error": null
    }
}
```

Если предыдущий парсинг ещё выполняется:

```text
409 Conflict
```

## `GET /api/organization/reviews?page=1`

Возвращает отзывы организации с серверной пагинацией.

Размер страницы:

```text
50 reviews
```

Пример:

```text
GET /api/organization/reviews?page=2
```

**Response:**

```json
{
    "current_page": 2,
    "data": [
        {
            "id": 51,
            "organization_id": 1,
            "external_id": "review-id",
            "author": "Имя автора",
            "rating": 5,
            "text": "Текст отзыва",
            "published_at": "2026-09-10T12:00:00.000000Z"
        }
    ],
    "per_page": 50,
    "total": 473,
    "last_page": 10
}
```

Frontend использует `current_page`, `last_page` и `total` для построения пагинации.

Во время выполнения Job frontend периодически запрашивает:

```text
GET /api/organization
```

и получает актуальный `parse_status` и `parse_progress`.

После завершения парсинга frontend загружает отзывы через:

```text
GET /api/organization/reviews?page=1
```

# HTTP-коды

| Код | Значение |
|---:|---|
| `200` | Успешный GET-запрос |
| `202` | Парсинг поставлен в очередь |
| `204` | Успешный login/logout без тела ответа |
| `401` | Пользователь не авторизован |
| `409` | Парсинг уже выполняется |
| `422` | Ошибка валидации данных |
| `404` | Организация не найдена |
| `500` | Внутренняя ошибка сервера |

Такое разделение позволяет frontend не зависеть от реализации парсера: Vue работает только с API и состоянием организации, а вся работа с Яндекс Картами остаётся на backend.

# Парсинг Яндекс Карт

## Почему не используется официальный API

Для задачи требуется получение отзывов организации.

Официального API Яндекс Карт для получения полного списка отзывов организации в используемом сценарии нет, поэтому получение отзывов выполняется через интерфейс Яндекс Карт.

При исследовании страницы было обнаружено, что веб-приложение Яндекс Карт само получает отзывы через внутренние HTTP-запросы. Однако прямое воспроизведение таких запросов с backend оказалось нестабильным: запрос зависит от контекста браузера, сессии и параметров, сформированных самим приложением.

Поэтому в качестве основного способа выбран браузерный парсинг.

## Выбранный подход: Puppeteer

Для загрузки страницы используется Puppeteer.

Puppeteer позволяет управлять Chrome/Chromium программно и получать доступ как к DOM, так и к сетевым событиям страницы.

Парсер:

1. открывает переданный URL Яндекс Карт;
2. проверяет наличие страницы отзывов;
3. получает информацию об организации;
4. перехватывает ответы внутренних запросов `fetchReviews`;
5. собирает отзывы;
6. прокручивает контейнер отзывов для загрузки следующих страниц;
7. удаляет дубликаты по `reviewId`;
8. останавливается после получения всех доступных отзывов либо после достижения лимита 600;
9. сохраняет результат во временный JSON-файл;
10. Laravel сохраняет данные в MySQL.

Таким образом, браузер выполняет JavaScript Яндекс Карт в максимально близком к обычному пользовательскому сценарию окружении.

# Сравнение подходов

## 1. Прямой HTTP-запрос к внутреннему JSON

### Плюсы

- высокая скорость;
- небольшое потребление памяти;
- не требуется запуск Chrome;
- удобно масштабировать большое количество запросов.

### Минусы

- внутренний endpoint не является публичным API;
- формат запроса и ответа может измениться;
- запросы могут зависеть от cookies, session ID, CSRF и других параметров браузерной сессии;
- необходимо самостоятельно воспроизводить браузерный контекст;
- изменения внутреннего API могут полностью сломать парсер.

Этот подход был исследован в процессе разработки, но для финального варианта не выбран как основной.

## 2. Headless Browser / Puppeteer

### Плюсы

- выполняется настоящий JavaScript страницы;
- используется реальный DOM;
- можно наблюдать сетевые запросы браузера;
- меньше зависимости от ручного воспроизведения внутреннего API;
- проще диагностировать изменения интерфейса;
- подходит для динамически загружаемых отзывов.

### Минусы

- значительно больше потребление CPU/RAM;
- запуск браузера занимает дополнительное время;
- один процесс парсинга существенно тяжелее обычного HTTP-запроса;
- при большом количестве организаций потребуется ограничивать параллелизм.

Для данного тестового выбран Puppeteer как более устойчивый и практически воспроизводимый вариант.

# Устойчивость к изменениям страницы

Парсер не должен молча сохранять пустой результат, если Яндекс изменил структуру страницы.

Перед началом сбора проверяется наличие блока отзывов.

Если ожидается наличие отзывов, но одновременно:

- карточки отзывов отсутствуют;
- API-ответы с отзывами не получены;

парсер завершает работу с ошибкой.

Laravel переводит задачу в состояние `failed` и сохраняет текст ошибки.

Это позволяет отличить:

```text
у организации действительно нет отзывов
```

от:

```text
парсер больше не может найти отзывы
```

Дополнительно в процессе работы логируются:

- номер страницы;
- количество полученных отзывов;
- количество новых отзывов;
- количество дубликатов;
- текущее количество собранных отзывов;
- общее количество отзывов;
- количество оставшихся отзывов;
- последняя обработанная страница.

# Ограничение в 600 отзывов

Яндекс указывает, что пользователю доступны последние 600 опубликованных отзывов.

Поэтому в парсере используется:

```js
const MAX_AVAILABLE_REVIEWS = 600;
```

Если у организации:

- 473 отзыва → собираются все 473;
- 600 отзывов → собираются все 600;
- 1822 отзыва → собираются последние доступные 600.

# Очередь и фоновые задачи

Парсинг не выполняется непосредственно внутри HTTP-запроса.

Это необходимо, поскольку запуск браузера и загрузка сотен отзывов может занимать десятки секунд или больше.

Job имеет:

- до 3 попыток выполнения;
- timeout 900 секунд;
- состояния `running`, `completed`, `failed`;
- прогресс от 0 до 100%;
- сохранение текста последней ошибки.

Во время работы Node.js отправляет прогресс через stderr:

```text
PROGRESS: 150/600
PROGRESS: 300/600
PROGRESS: 450/600
PROGRESS: 600/600
```

Laravel читает эти сообщения и обновляет `parse_progress`.

Frontend периодически получает актуальное состояние организации через API и показывает прогресс пользователю.

# Защита от повторного запуска

Если парсинг уже выполняется, повторный запуск не создаёт вторую параллельную задачу.

API возвращает HTTP `409`.

Это предотвращает ситуацию, когда несколько браузеров одновременно собирают отзывы одной организации.

# Дубликаты и повторный парсинг

Каждый отзыв сохраняется с внешним идентификатором:

```text
organization_id + external_id
```

В базе используется уникальное ограничение:

```text
unique(organization_id, external_id)
```

При новом успешном парсинге текущий набор отзывов организации синхронизируется заново.

Это позволяет повторно запускать парсер без накопления дублей.

# Обработка ошибок

Ошибки обрабатываются на нескольких уровнях.

### URL

Некорректная ссылка не проходит Laravel validation.

Проверяется:

- корректность URL;
- домен Яндекс;
- путь `/maps`;
- наличие раздела отзывов.

### Парсер

Ошибки Puppeteer и Node.js передаются обратно в Laravel.

### Queue Job

При ошибке:

```text
parse_status = failed
```

и сохраняется:

```text
parse_error
```

После исчерпания попыток Laravel Queue вызывает `failed()` Job.

### Frontend

Vue отображает пользователю:

- состояние загрузки;
- прогресс;
- сообщение об ошибке;
- состояние успешно завершённого парсинга.

# Anti-ban / нагрузка

Парсер не пытается отправлять большое количество параллельных HTTP-запросов к Яндексу.

Вместо этого используется последовательная загрузка страниц через один экземпляр браузера.

Между действиями присутствуют небольшие паузы, а отзывы загружаются штатным механизмом страницы при прокрутке.

Для production-версии при масштабировании на десятки организаций дополнительно предусмотрел бы:

- ограничение количества одновременно работающих браузеров;
- очереди с ограниченной concurrency;
- exponential backoff для повторных попыток;
- отдельную обработку HTTP 403/429 и признаков блокировки;
- распределение нагрузки между worker-процессами;
- при необходимости — управляемые proxy.

Ротация proxy и User-Agent в текущем тестовом проекте намеренно не реализована: для демонстрационного прототипа это добавило бы сложность без необходимости.

# Idempotency и история

Повторный запуск парсинга не должен создавать дубликаты.

Для этого отзыв идентифицируется внешним `reviewId`, а в базе существует уникальная комбинация:

```text
organization_id + external_id
```

В текущей версии база хранит актуальное состояние отзывов организации.

Для production-версии можно добавить историю изменений:

```text
review_snapshots
```

с хранением:

- времени парсинга;
- текста;
- оценки;
- автора;
- даты публикации;
- внешнего идентификатора.

Это позволит отслеживать появление, изменение и удаление отзывов между запусками.

# Локальный запуск

## Backend

Перейти в каталог:

```bash
cd backend
```

Установить зависимости:

```bash
composer install
npm install
```

Создать `.env`:

```bash
cp .env.example .env
```

Сгенерировать ключ:

```bash
php artisan key:generate
```

Настроить подключение к MySQL в `.env`.

Выполнить миграции и seed:

```bash
php artisan migrate --seed
```

Запустить Laravel:

```bash
php artisan serve
```

В отдельном терминале запустить Queue Worker:

```bash
php artisan queue:work
```

## Frontend

```bash
cd front
npm install
npm run dev
```

После запуска открыть адрес Vite, указанный в консоли.

# Переменные окружения

Основные настройки Laravel находятся в `.env`.

В частности:

```env
APP_URL=http://127.0.0.1:8000

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=...
DB_USERNAME=...
DB_PASSWORD=...

QUEUE_CONNECTION=database
```

Секреты и реальные credentials в репозиторий не добавляются.

# Что можно улучшить при наличии дополнительного времени

1. Добавить полноценную историю изменений отзывов.
2. Разделить парсинг и сохранение результатов через staging-таблицу.
3. Добавить отдельные статусы `blocked`, `retrying`, `timeout`.
4. Реализовать ограничение concurrency для браузерных workers.
5. Добавить автоматические тесты парсера на сохранённых HTML/JSON fixtures.
6. Добавить мониторинг Queue и длительности парсинга.
7. Добавить Docker Compose для запуска Laravel, MySQL, Node.js и Queue Worker одной командой.
8. Добавить более независимые от CSS-селекторов способы обнаружения элементов страницы.
9. При масштабировании рассмотреть пул браузеров вместо запуска отдельного браузера для каждой задачи.

# Примечание

Проект предназначен для демонстрации архитектуры и подхода к сбору данных из динамического веб-приложения.

Парсер использует публично доступную веб-страницу Яндекс Карт и браузерный сценарий работы с ней. Формат внутренних запросов и структура страницы не являются стабильным публичным API, поэтому в production необходимо предусмотреть регулярную проверку и адаптацию парсера при изменениях Яндекс Карт.
